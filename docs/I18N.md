# Internationalization

`src/shared/i18n/index.ts` owns the English/French preference, observable language changes and translation lookup. English source messages are keys in `fr.json`; interpolation preserves user-supplied names and values. `document.documentElement.lang` follows the interface preference.

Use `t()` for interface copy and human-readable module exports. Report composition receives an explicit language and uses `translate()` instead of mutating the global interface preference. Renderers format report dates and numbers with that language. A report language can differ from the interface language.

Do not translate project titles, recorded rationale, risks, accepted notes or source story text. Typed codes and JSON field names remain stable interchange identifiers. CSV headings and Markdown/report headings are human-readable and localized.

New copy requires a catalog entry. Tests scan static `t('...')` calls, validate the maintained catalog and exercise known dynamic domain messages. Dynamic labels and new error messages also need explicit review; static extraction alone does not prove complete translation coverage. Do not add guessed translations of user content.

Browser checks exercise nine exact viewports in both interface languages, two themes on studio accessibility checks and real French/English PDF/PPTX outputs. Noto fonts are bundled under their OFL license for PDF. Unsupported characters cause a visible export error with a structured-export alternative rather than silent deletion. Complete font/script coverage and linguistic review by every target audience remain outside current evidence.
